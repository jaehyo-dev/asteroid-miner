- 출격(2배)과 기지(3배)는 화면이 달라서 허용. 전환은 페이드로 가림.

**코드로 그린 그림 목록 (`draw_*` 호출 수: world_view 31, hud 17, gate_view 12, base_view 7, danger_overlay 5, app 4, base_panel 2, joystick 2, starfield 1)**

## 4. 화면 확대 방식 비교 → **D 선택 (정수 배율 + 논리 화면 자동 조절)**

실제 캡처로 비교 (`review/stretch_compare.png`, `review/stretch_compare_win1366.png`). 같은 우주선(9x7)을 1366x657 브라우저 창(PC 노트북에서 흔한 비정수 크기)에서 비교:

| 방식 | 배율 | 가장 넓은 줄의 픽셀 폭 | 결과 |
|---|---|---|---|
| A 지금 (`canvas_items` 소수) | 1.83 | 3·2·6·1·4 칸이 섞임 | 픽셀이 들쭉날쭉, 좌우 비대칭 |
| B `viewport` 소수 | 1.83 | A와 같음 | A와 차이 없음 |
| C 정수만(`scale_mode=integer`) | 1 | 균일 | 픽셀은 고르지만 1배로 줄어 우주선이 너무 작고 검은 띠 큼 |
| **D 정수 + 논리 화면을 창/배율로 조절** | **2** | **균일(24·14·23)** | 고르고 크게 나옴. 논리 화면이 683x328처럼 조금 달라짐 |

- PC 1280x720은 A~D 모두 2배라 동일. 폰 가로(844x390 DPR3, 915x412 DPR2.6)는 실제 픽셀 기준 약 3~3.25배라 A·B도 거의 보통이지만, 브라우저 창·저DPR 기기에서는 D만 고름.
- D 규칙: `k = round(min(창.x/640, 창.y/360))`, 논리 화면이 560x320 아래로 줄면 k를 낮춤, 논리 화면 = 창/k. 시험용 구현은 이미 돌려 봤고(`App.fit_screen`에 7줄) 콘솔 오류 0. 단점: 화면 높이가 328~360 사이로 달라짐(HUD는 앵커라 영향 작음), 적·운석 생성 구역은 논리 화면 크기를 읽도록 확인 필요.
- 기지 화면은 지금처럼 1280x720 고정(3배 그림). 건드리지 않음.

## 6. 규모가 커지는 문제 (꼭 확인)

팩 그림은 지금 게임보다 **약 3배 크다**: 우주선 9x7 → 약 26x28, 운석 지름 12~30 → 팩 한 종류 약 50x44. 따라서
1. 충돌 반지름·생성 거리·속도·광물 흩어짐 등 `balance.gd` 수치를 새 그림 크기에 맞춰 다시 맞춤 (밸런스 값만 바꾸고 난이도 곡선은 유지, 테스트가 걸린 수치는 같이 고침).
2. 팩에 운석이 1종뿐이라 작은·중간·큰(1 : 1.6 : 2.5)을 만들려면 **작은 것과 큰 것을 Codex로 팩 스타일·팔레트로 추가**해야 함. 팩 운석(보이는 폭 약 50)을 "중간"으로 쓰면 작은 ≈ 31, 큰 ≈ 78. 정수 배율로 키우거나 줄이는 건 ART_BIBLE 1번 위반이라 안 함.

## 7. QUALITY_BAR 구현 계획 (수치는 `scripts/juice.gd` 한 곳, 상수만 있는 Balance와 같은 방식)

| 항목 | 구현 |
|---|---|
| 총구 불꽃+반동 | 발사 때 Auto Cannon 프레임 재생 + 우주선을 뒤로 1~2px 밀었다 돌아오는 트윈(0.08s) |
| 맞은 적 흰 번쩍+밀림 | 지금 `flash` 시간(50ms) 유지, 텍스처 대신 흰색으로 칠하는 셰이더(modulate 흰색 믹스)로 팩 그림에 적용. 밀림은 `knock_offset` 재사용 |
| 폭발+파편, 크기별 | 팩 Destruction 시트 재생 + 파편 파티클(코드). 작은=Nairan 시트, 큰=Kla'ed 큰 시트+운석 조각 시트 |
| 큰 운석만 히트스톱+흔들림 | `run.gd` 시뮬 진행을 30~60ms 멈춤(Engine.time_scale 안 씀, 입력·소리는 계속) + 약한 흔들림 |
| 광물 튕김·감속, 자석 가속, 줍기 반짝+소리 | 광물 생성 때 방사 속도+ease-out, 자석은 거리에 반비례 가속, 줍기는 반짝 스프라이트 + 연속 줍기 시 음 높이 상승(1초 안 연속, 최대 +12반음) |
| 등급 구분 | 팔레트 4색(회색·시안·보라·금) + 등급별 반짝 빈도 + 등급별 소리(음색) |
| 방향 전환 보간, 엔진 세기 | 우주선 각도를 `lerp_angle`로, 속도에 따라 Idle/Powering 프레임 전환 |
| 피격 연출 | 중간 흔들림, 화면 가장자리 빨간 테두리(이미 있는 `danger_overlay` 확장), 무적 깜빡임, 피격음 |
| 레벨업 | 슬로모션 0.25배 0.3s + 빛 + 카드가 튀어 오르며(overshoot 트윈) 등장 |

## 9. 승인과 추가 범위 (2026-11-08, 사용자 승인)

8번의 1~5를 모두 추천안대로 승인함: D 방식 화면 확대, 작은·큰 운석 Codex 추가, 적 3종 매핑과 이름 유지, 새 그림 크기에 맞춘 수치 재조정(난이도 곡선 유지), 버튼은 1px 눌림 + 색 변화.

승인 조건: 충돌 판정은 그림보다 작게, 밸런스 봇으로 한 판 길이·사망률을 바꾸기 전과 비교, 운석·적 파괴는 팩 explode 애니메이션 사용, 배경 별은 3겹 시차, HUD의 광물 개수·게이트 시간 표시를 유지(빠지면 복원).

이 계획서를 쓴 뒤 정해진 범위(GAME_SPEC.md 11번)를 7번 표에 더한다:

| 항목 | 구현 |
|---|---|
