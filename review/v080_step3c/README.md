## 1. 레일건 사거리 (무한)

- 조준: 화면 안에 몸이 조금이라도 보이는 대상 중 가장 가까운 것(`RunSim.rail_target`). 화면 밖은 노리지 않음.
- 빛줄기 길이 = 화면 대각선(`view_size.length()`): 화면 안 어디서 어느 쪽으로 쏴도 화면 밖까지 감. PC 1280x720·폰 844x390·다중 포신 3갈래에서 끝점이 모두 화면 밖인지 자동 테스트로 확인. 선 위의 화면 밖 대상도 맞음.
- 굵기: 사거리를 올리는 강화의 배율을 그대로 곱함(`rail_width = width × 사거리 배율`, 상한 `Balance.RAIL_WIDTH_MAX` = 10). 판정과 그림이 같은 값을 씀. 빛줄기는 적·운석·적 탄·내 우주선보다 아래에 반투명으로 그려져 굵어져도 우주선과 적 탄이 위에 보임(`rail_wide.gif`).
- 레벨업 사거리 카드: 레일건일 때 "빛줄기 굵기 5.0 → (다음 굵기)"로 보임(`RunSim.rail_card_text`).
- 격납고: 사거리 "무한", 무기 4칸 막대 사거리는 가득(5칸), 다른 무기와 비교할 때 사거리 ▲▼는 안 나옴(레일건을 고를 때도, 레일건을 낀 채 다른 무기를 고를 때도).
- 드론 사거리는 그대로(레일건 `range` 300을 드론 사거리 기준으로만 씀).

## 2. 레일건 히트박스: 찾은 원인과 고친 것

| 원인 | 증상 | 고침 |
|---|---|---|
| **판정 반지름이 그림보다 작음**: 적·운석의 `radius`는 우주선과 부딪히는 판정용이라 보이는 몸의 약 70%로 잡혀 있음(큰 운석 20 vs 몸 약 28) | 빛줄기가 운석 그림 가장자리를 지나가도 안 맞음 (그림에는 닿았는데 안 맞음) | 레일 판정만 보이는 몸 크기(`radius × 1.4`, `Balance.RAIL_BODY_RADIUS_MULT`)로. 디버그 캡처에서 하늘 원이 운석·해파리 그림 가장자리와 맞는 것 확인 |
| **빛줄기가 쏜 뒤에도 우주선을 따라 움직임** (3b에서 "총구에 붙게" 한 것): 판정은 쏜 순간 한 번인데, 그림은 0.7초 동안 우주선과 같이 평행 이동 | 빠르게 움직이면 빛줄기가 맞지 않은 대상 위를 쓸고 지나가 보임 (안 닿았는데 지나감) | 빛줄기 그림은 쏜 순간 판정한 선(시작·끝·굵기)을 fx로 받아 그 자리에 남김(`weapon_fx.gd trail_ends`). 충전 빛·총구 섬광은 계속 총구에 붙음 |
| **판정 시작점과 그림 시작점이 다름**: 판정은 우주선 가운데에서, 그림은 총구(조준 방향 10픽셀 앞)에서 그 갈래 각도로 그림 | 다중 포신 옆 갈래는 그림과 판정이 약 2픽셀 평행으로 어긋남 | 위와 같이 같은 선 자료를 쓰므로 갈래마다 방향·위치가 같음 |
| 굵기 | 그림은 `Weapons.info("rail").width` 고정, 판정도 고정 | 둘 다 `sim.rail_width` |

- 자동 테스트: 빛줄기 그림 시작·끝·굵기 = 판정 선(다중 포신 갈래마다, 최고 속도로 0.5초 움직이는 동안), 몸이 굵기 안에 걸치면 맞고 1픽셀 밖이면 안 맞음, 화면 밖 대상은 노리지 않음, 화면 밖이어도 선 위면 맞음.
- 빠르게 움직이면 빛줄기 시작점이 우주선 뒤에 남는 게 보인다(최고 속도라면 밝은 부분이 보이는 약 0.2초 동안 수십 픽셀). 판정과 그림이 같다는 쪽을 골랐다.

## 3. 채굴 빔 치명타 0

- 원인: 실제 피해는 0이 아니었음(빔 한 번 0.22 × 치명타 2 = 0.44). 화면 숫자가 실제 피해(체력 단위)를 반올림해서 0이 됐음. 다른 무기도 한 발 피해가 0.5 아래면(빔의 적 피해 0.5배 등) 같은 문제.
- 고침: 치명타 숫자를 격납고 "공격력"과 같은 단위(실제 피해 × 100, 최소 1)로 보여 줌(`Weapons.shown_damage`). 빔 치명타 = 44, 펄스 치명타 = 200. 같은 대상의 치명타가 0.3초 안에 또 나오면 새 숫자를 띄우지 않고 떠 있는 숫자에 더함(`Juice.CRIT_MERGE_TIME`) → 빔은 "132"처럼 모아서 보임. 표시 합 = 실제 피해 합 × 100.
- 자동 테스트: 빔 치명타 실제 피해 > 0, 표시 숫자 > 0이고 = 실제 × 100, 모은 숫자 합 = 실제 피해 합.

## 4. 건너뛰기 버튼

- "건너뛰기 +7" → "건너뛰기 (보상 광물 7)". 예전엔 좁으면 "광물"을 빼서 숫자만 남았음. 이제 글자가 다 들어가게 버튼 폭을 넓힘(두 버튼 같은 폭, 판 그림 양 끝 화살표 장식 안쪽). 자동 테스트: 폰 844x390부터 작은 화면 560x320까지 모든 화면에서 보상 1234일 때도 버튼 줄이 화면 안.

## 5. 연구소 선행 조건

- 원인: `Research._passed`가 "곧 추가" 칸을 건너뛰고 그 아래 칸을 봄 → 펄스 증폭기만 연구해도 보조 무기 해금(곧 추가) 위 갈림길이 열렸음.
- 고침: "곧 추가" 칸은 지나지 못함 → 그 위 칸 모두 잠김. 연구소 관 빛도 같은 규칙(`ResearchLayout._lit`). 잠긴 칸 설명은 "먼저: 보조 무기 해금 (곧 추가)".
- 다섯 가지 점검 결과: 다르게 되어 있던 곳은 **무기 가지(보조 무기 해금 → 갈림길·증폭 탄창)** 하나. 탐사 가지 "항로 개척"도 곧 추가지만 맨 위라 위 칸이 없음. 선체·채굴·전자 가지는 곧 추가 칸이 없고, 이미 "아래 칸 1단계 이상(갈림길은 한쪽 이상 해금)" 규칙이었음.
- 예전 저장: 이미 산 칸·갈림길은 그대로(사용 중, 효과 그대로), 그 위 칸도 계속 열림. 안 산 반대쪽만 새 규칙대로 잠김.
- 자동 테스트: 다섯 가지 모든 칸에서 아래 칸 0단계면 잠김·1단계면 열림, 곧 추가 위는 계속 잠김, 예전 저장의 갈림길 유지.

## 6. 선택 테두리 없애기

| 화면 | 예전 | 지금 |
|---|---|---|
| 격납고 [전투기]/[기본 무기] 탭 | 노란 테두리 | 금빛 글자 + 바탕을 옅은 금색으로 채움 |
| 격납고 전투기 칸 | 노란 테두리 | 판을 살짝 밝게 |
| 격납고 무기 카드 | 장착 중 노란, 고름 하늘 테두리 | 고른 카드는 판을 살짝 밝게, 장착 중은 "장착 중" 금빛 글자 |
| 연구소 고른 칸 | 흰 테두리 빛 | 칸 그림을 밝게 (연구 상태 빛은 그대로) |
| 연구소 갈림길 설명 카드 | 고른 쪽 흰 테두리, 사용 중 테두리 | 고른 쪽 바탕을 밝게 |
| 전시관 고른 칸·고른 상자 | 흰 테두리 | 뒤 바탕을 옅게 밝힘 |
| 전시관 받을 수 있는 상자 | 금빛 테두리 깜빡 | 상자 그림만 금빛으로 깜빡 |
| 기지 건물 (마우스·키보드) | 하늘색 윤곽선 | 건물 그림을 밝게 |
| 레벨업 카드 (마우스 올림) | 흰 빛 테두리 2겹 | 카드 전체를 살짝 밝게 (등급 빛 띠는 등급 표시라 그대로) |

- 일시 정지·설정·결과 메뉴 버튼, 기지 HUD 버튼, 닫기·창 버튼은 원래 테두리 스타일이 없었음(자동 테스트로 확인). Godot focus 스타일은 테마에서 이미 비어 있음. 키보드로 고른 버튼의 양옆 작은 금빛 눈금(선이 아님)은 키보드 조작용으로 남김.
- 자동 테스트: `tests/test_no_select_border.gd`(기지·건물 창 5개·레벨업 카드·일시 정지의 모든 버튼: 테두리 있는 스타일, 비어 있지 않은 focus 스타일이 있으면 실패), `tools/test_ui_rules.py`(UI 스크립트에서 직접 그리는 테두리 선은 허용 목록(말풍선·메뉴 창·연구 판 틀, 카드 등급 빛)만).
