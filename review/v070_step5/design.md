# v0.7.0 5단계 1부: 레벨업 카드 설계 시안

**게임에는 아직 아무것도 적용하지 않았어요.** 여기 있는 수치와 이름은 모두 제안이고, 고르신 뒤에 구현해요.

> 1차 선택은 끝났어요. 결정과 새 프레임 시안은 맨 아래 "6. 선택 결과와 카드 프레임 시안"에 있어요.

## 골라 주실 것 (1차, 끝남)

1. 카드 시안: A, B, C 중 하나 (섞어도 돼요)
2. 폰 설명 글자: 12px 또는 24px
3. 레전드리 특별 효과 6개 중 4개
4. 효과 카드 보정: 넣을지 말지 (아래 "확률과 수치"의 충돌 참고)

## 1. 카드 화면 시안

모두 진짜 출격 화면(같은 시드, 1분 20초) 캡처 위에 올렸어요. 파일은 `mock_{A,B,C}_pc_1280x720.png`, `mock_{A,B,C}_phone_844x390.png`, 다섯 등급 비교 `mock_{A,B,C}_grades.png`예요.

| | A 격납고 패널 | B 장갑판 | C 스캔 창 |
|---|---|---|---|
| 테두리 | 모서리를 깎은 굵은 선 | 곧은 얇은 선 + 네 모서리에 굵은 ㄱ자 쇠 | 얇은 선 + 모서리 살짝 깎음, 판이 조금 비침 |
| 아이콘 (48px 원본) | PC 2배 96 / 폰 3배 144, 어두운 칸 안 | PC 3배 144 / 폰 3배 144, 칸 없이 크게 | PC 2배 96 / 폰 2배 96, 스캔 줄 칸 안 |
| 글자 배치 | 가운데 정렬, 아이콘 → 이름 → 종류 → 설명 | 왼쪽 정렬, 이름이 등급 색 | 왼쪽 정렬, 이름이 맨 위 → 종류 → 아이콘 → 설명 |
| 단계 점 | 맨 아래 가운데 | 왼쪽 아래 (종류 표는 오른쪽 아래) | 아이콘 옆 세로 눈금 |
| 배경 처리 | 화면 전체를 고르게 어둡게 | 가운데는 진하고 가장자리로 갈수록 화면이 보임 (3단 계단) | 조금만 어둡게 + 위아래 검은 띠 |
| 폰 이름 / 설명 | 24px / **12px** | 24px / 24px | 24px / 24px |

**추천: B + 설명 24px.** 아이콘이 가장 크고 이름이 등급 색이라 등급이 빨리 읽혀요. 다만 C는 뒤 전투 상황이 가장 잘 보이고 카드가 낮아요.

### 폰에서 글자가 읽히는지

폰의 논리 화면은 844x390이라 1논리 픽셀이 CSS 1픽셀이에요 (`App.run_pixel_scale`: DPR3 폰은 실제 3배). 폭 약 147mm 폰으로 계산한 글자 높이예요.

| 글자 | 실제 높이 | 판단 |
|---|---|---|
| 24px (이름, B·C 설명, 버튼) | 약 4.2mm | 캡처에서 또렷함, 편하게 읽힐 크기 |
| 12px (A 설명, A 종류 표) | 약 2.1mm | 캡처로는 읽히지만 작음. 지금 HUD 글자와 같은 크기 |

그래서 폰은 **설명 24px을 추천**해요. "효과 설명은 작게"와는 조금 달라져요: 폰에서 이름과 설명이 같은 크기라 색으로 구분해요. 실제 폰으로는 아직 보지 못했어요. PNG를 폰 가로 화면에 꽉 채워 보면 실제 크기와 거의 같아요.

### 픽셀 배율

- PC는 카드 층 전체를 640x360 논리 픽셀로 그린 뒤 2배, 폰은 1배로 정수 확대만 했어요. 글자는 Galmuri11 12px과 그 2배 24px만, 앤티에일리어싱 없이 그렸어요.
- **규칙에서 벗어나는 점**: 아이콘이 2·3배라 뒤 출격 화면(1배)과 픽셀 크기가 달라요. 또 이름 24px과 설명 12px도 글자 픽셀 크기가 달라요. 지금 메뉴 제목(24px)과 본문(12px)도 같은 방식이고, 카드는 어두운 판 위 별도 층이라 허용으로 판단했어요. 격자를 완전히 하나로 맞추려면 아이콘을 96~144px 원본으로 그려야 해요.
- 빛은 일정한 알파의 계단 띠라 픽셀 격자를 벗어나지 않아요. 띠 수는 등급마다 1(노멀)~5(레전드리)개예요.
- PC 창이 작으면 논리 높이가 최소 320까지 줄어요. B(카드 296 + 버튼 26 = 322)는 2픽셀 넘쳐서, 구현할 때 카드를 조금 줄여야 해요.

### 같은 그림을 쓴 부분

다섯 등급 비교에서 노멀·레어는 같은 쿨러, 레전드리는 관통탄 아이콘을 다시 썼어요 (샘플이 3개뿐이라서). "궤도 관통 가속기"는 후보 1번 이름이에요. 레전드리의 빛이 흐르는 움직임은 구현 때 넣어요 (시안은 정지 화면).

## 2. 아이콘 스타일 샘플

`icons/cooler.png`, `pierce.png`, `drone.png`: 48x48, void32 팔레트 8~10색, 외곽선 #2b1925 계열, 빛은 왼쪽 위. 요청문은 `ASSET_PROMPTS.md`, 원본은 `assets/raw/run/icons/`, 정리는 `make_icons.py`예요.

- 팔레트 8~10색으로 팩 그림과 어울려요. 다만 **아이콘은 48px이라 작은 우주선(몸 약 15px)보다 훨씬 세밀**해요. 카드 위에 크게 보이는 그림이라 괜찮다고 봤어요.
- 관통탄은 첫 장이 뭉쳐 보여 1번 다시 만들었어요. 지금도 쿨러·드론보다 가늘어서 칸을 덜 채워요. 스타일이 정해지면 탄을 더 굵게 다시 만들 생각이에요.
- `tools/pixelate.py`는 이 그림에서 외곽선을 잃고 강조색을 바꿔서, 블록마다 가장 많은 색을 고르는 방식으로 정리했어요 (`tools/make_minerals.py`도 비슷한 이유로 따로 있음).

### 판단이 필요한 충돌: 효과 카드가 드물어요

설계서의 "카드 3장은 수치와 효과가 섞이도록"과 "효과 강화는 에픽부터"가 부딪혀요. 시작 때 에픽 이상은 18%뿐이라, 대부분의 레벨업 화면에는 효과 카드가 없어요. returner 기준 한 판에 약 1.9장, **14%의 판은 효과 카드를 한 번도 못 봐요.**

**제안: 효과 카드가 없는 레벨업이 2번 이어지면 다음 화면에 에픽 효과 1장 확정.** returner는 2.5장으로 늘고, 못 보는 판이 0%가 돼요. 위 "보정 있음" 줄이 그 결과예요.

### 수치 강화 8종

노멀은 지금 값의 약 3/4로 낮춰요. 시작 때 평균 배율이 ×1.36이라, 이렇게 하면 평균 강화량이 지금과 비슷해요. 발사 속도는 설계서 예시(+10/15/20/30%)를 따랐어요.

| 시스템 쿨러 개량 | 공격 | 발사 속도 약 +18% | +10% | +15% | +20% | +30% | 5 |

| 고밀도 탄두 | 공격 | 탄 피해 +1 | +0.75 | +1.1 | +1.5 | +2.25 | 5 |

## 5. 편향 실드 연출 시안

`shield_frames.png`: 진짜 우주선 그림(60% 크기)에서 윤곽을 뽑아 그렸어요. 위쪽은 5배 확대, 오른쪽은 실제 크기(PC 2배, 폰 1배)예요.

- 충전 중: 투명에서 진해짐 (1/3, 2/3, 거의 참). 바깥 빛도 함께 강해짐
- 완충: 흰 빛줄기가 윤곽을 따라 한 바퀴 흐름 (4프레임). 시트에 없는 "가끔 은은한 반짝임"은 구현 때 넣어요
- 막는 순간: 희게 번쩍 → 윤곽 조각이 금·주황으로 흩어지며 사라짐
- 폰 1배에서는 윤곽이 1픽셀이라 얇아요. 조각 연출은 보이지만, 충전 단계 차이는 작아서 실제 폰에서 꼭 볼 부분이에요.

## 6. 선택 결과와 카드 프레임 시안

### 확정된 것 (계획서 23번)

- 레전드리 4개: 궤도 관통 가속기, 연쇄 반사 매트릭스, 과부하 반응로, 전역 견인 비콘
- 효과 카드 보정 넣음: 효과 카드 없는 레벨업이 2번 이어지면 다음 화면에 에픽 효과 1장 확정
- 폰 설명 글자 24px
- 다시 뽑기: 카드 3장 아래 가운데 버튼 하나로 3장을 동시에 새로 뽑음, 한 판 2번

위 4번의 봇 추정에는 다시 뽑기가 들어 있지 않아요. 3장을 한꺼번에 뽑으면 한 판에 최대 6장을 더 보니, 실제 등급 등장 수는 조금 늘어요.

### 골라 주실 것

**프레임 방향 하나: M 또는 S. 추천은 S예요.**

자료는 `frame/`에 있어요. 방향마다 `frame_{M,S}_pc_1280x720.png`, `frame_{M,S}_phone_844x390.png`, 다섯 등급과 버튼 상태 `frame_{M,S}_grades.png`, 등장 연출 `frame_{M,S}_reveal.png`, 등급별 빛 `frame_{M,S}_reveal_glow.png`예요.

| | M 각진 군용 장갑판 | S 매끈한 고급 기술 장비 |
|---|---|---|
| 프레임 | 사선으로 잘린 모서리, 겹친 장갑판, 볼트, 판 이음매 | 둥근 모서리, 밝은 세라믹 판, 정밀 나사, 얇은 이음선 |
| 아이콘 받침 | 각진 육각형 | 매끈한 원형 |
| 등급 장식 | 큰 날개가 묵직한 금속 덩어리 | 큰 날개가 곡선이라 윤곽이 또렷함 |
| 카드 높이 (PC / 폰) | 255 / 299, 버튼 포함 289 / 344 | 277 / 325, 버튼 포함 311 / 370 |
| 장점 | 카드가 낮아 뒤 화면이 더 보임. 팩의 우주선과 결이 비슷함 | 등급 차이가 작은 화면에서도 잘 보이고 이름 칸이 시원함 |
| 약점 | 유니크·레전드리 장식이 작은 화면에서 뭉쳐 보임 | 카드가 높아 폰 화면을 거의 다 씀 |

**추천 이유**: 폰에서 장식이 또렷하고 원형 받침이 아이콘을 잘 살려요. 다만 M이 게임의 묵직한 분위기에는 더 가까워요. 눈으로 보고 정해 주세요.

### 등급별 차이

| 등급 | 프레임 | 장식 | 빛 |
|---|---|---|---|
| 노멀 | 수수한 금속, 발광 띠 꺼짐, 이름은 밝은 흰색 | 꺼진 보석 | 없음 |
| 레어 | 금속 + 시안 발광 띠 | 빛나는 보석 | 띠 2겹 |
| 에픽 | 금속에 보라 기운 + 보라 띠 | 작은 날개 추가 | 띠 3겹 |
| 유니크 | 금속이 금색 | 큰 날개 + 위쪽 모서리 쇠 | 띠 4겹 |
| 레전드리 | 금색 + 두꺼운 띠와 발광 띠가 무지개로 흐름 | 큰 날개 + 네 모서리 쇠 | 띠 5겹, 무지개 |

### 프레임을 만든 방법

- 그림은 Codex로 방향마다 2장씩 총 4장이에요 (빈 프레임 1장, 부품 시트 1장). 요청문은 `ASSET_PROMPTS.md`, 원본은 `assets/raw/run/frame/`이에요. 다른 게임 이름은 넣지 않았어요.
- `frame/make_frames.py`가 블록마다 가장 많은 색을 골라 void32 색으로 바꿔요. 정리한 부품은 `frame/parts_{M,S}/`에 있어요.
- **9칸 나누기**: 프레임 원본 192x288 한 장으로 모든 크기를 만들어요. 모서리 70x84는 그대로 두고 변과 가운데만 반복해요. 이 시안의 PC 196x255~277과 폰 262x299~325가 모두 같은 원본이에요.
- **등급은 색 바꾸기**: 청록 부분은 등급 색으로, 금속은 등급별 색표로 바꾸고 장식을 더해요. 등급마다 그림을 따로 만들지 않아요.
- 카드 높이는 가장 긴 내용에 맞춰 계산해서 설명 아래 빈 공간을 없앴어요. 입체감은 프레임 그림의 위 밝은 면·아래 어두운 면에 더해, 안쪽 판 위아래에 계단식 밝기 띠를 얹었어요.
- 글자 구역에 회로 홈이 지나가면 읽기 어려워서, 받침 아래쪽 홈은 지웠어요. 위쪽 홈은 남겼어요.
- 프레임 위쪽 장식은 카드 바로 위로 튀어나와요.

### 다시 뽑기 버튼

프레임과 같은 결의 판 그림을 쓰고, 폭은 9칸 나누기로 맞췄어요. 남은 횟수가 있으면 "다시 뽑기 2회", 0회면 회색으로 어둡게 꺼지고 글자도 흐려져요. `frame_{M,S}_grades.png` 아래쪽에 두 상태가 함께 있어요.

### 등장 연출 (`frame_*_reveal.png`, PC 기준 대표 프레임)

| 시각 | 일어나는 일 |
|---|---|
| 0.10초 | 뒤 화면이 어두워짐 |
| 0.20초 | 첫 카드가 뒷면으로 내려옴 |
| 0.31초 | 내려온 자리에서 뒤집힘 (폭이 줄었다 늘어남, 픽셀 격자 유지) |
| 0.40초 | 앞면이 번쩍이며 나타남 |
| 0.70초 | 둘째 카드가 앞면으로 번쩍임 |
| 0.98초~1.05초 | 셋째 카드(레전드리)가 가장 강하게 번쩍이고 빛이 넓게 퍼짐 |
| 1.50초 | 자리 잡음. 무지개가 계속 흐르고 버튼이 나타남 |

- 등급이 높을수록 번쩍임이 세고 빛 고리가 넓어요 (`frame_*_reveal_glow.png`). 소리는 이번 시안에 없어요.
- 시간은 시작값이에요. 지금 입력 지연 0.35초보다 길어서, 구현 때 "카드가 다 나오기 전에는 못 고르게 할지, 눌러서 건너뛰게 할지"를 정해야 해요. 저는 눌러서 건너뛰기를 제안해요.

### 지켜야 할 규칙에서 벗어나는 점과 구현 때 할 일

- **픽셀 배율**: 프레임·장식·꼬리표·버튼은 PC·폰 모두 논리 1배로 뒤 화면과 격자가 같아요. 받침과 아이콘은 2배, 글자는 12px·24px이라 이 부분은 여전히 픽셀 크기가 섞여요 (카드를 올리는 층이라 허용으로 판단, 1차와 같음).
- **폰 크기가 더 작은 기기**: 915x412(DPR 2.6) 폰은 논리 화면이 793x357이에요. 시안의 폭 810은 두 방향 다 넘치고, 높이 370(S)도 넘쳐요 (M은 344라 들어가요). 구현할 때 논리 화면에 맞춰 카드 폭과 받침 크기를 조절해야 해요. 이 크기는 캡처하지 않았어요.
- **PC 작은 창**: 논리 높이 최소 320에서 M(289)과 S(311)는 들어가요. 폭 최소 560은 카드 폭을 줄여야 해요 (지금 3장 폭 608).
- **아이콘**: 다섯 등급 비교는 아직 샘플 3개를 다시 써요. 나머지 12종은 프레임이 정해진 뒤에 만들어요.
- 레전드리 무지개가 흐르는 모습은 정지 프레임으로만 확인했어요. 실제 움직임은 구현 뒤에 봐야 해요.
