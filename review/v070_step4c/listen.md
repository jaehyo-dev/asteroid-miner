# 4c 3차 후보: Urgent 위에 얹는 음 층

## 들어 볼 파일

`_start` = 기지에서 출격하는 순간부터 45초 (베이스 + 30초에 리듬 층). `_2min` = 게임 1분 50초부터 40초 (2분에 빠른 리듬 + 멜로디가 들어옴).

| 후보 | 파일 | 주인공 | 1분 층 | 2분 멜로디 음색 | 베이스 |
|---|---|---|---|---|---|
| ★ a | `bgm3_a_start.ogg`, `bgm3_a_2min.ogg` | 어두운 신스 아르페지오 | 16분음표 아르페지오 + 메아리 | 같은 음색의 긴 플럭 | 단순 |
| b | `bgm3_b_start.ogg`, `bgm3_b_2min.ogg` | 패드 화음 + 베이스 | 천천히 부푸는 패드 3음 | 부드러운 금속성 음 | 8분음표로 움직임 |
| c | `bgm3_c_start.ogg`, `bgm3_c_2min.ogg` | 짧은 리드 멜로디 | 엇박 화음 찌르기 | 네모파에 가까운 리드 (가장 앞에 나옴) | 단순 |

a를 고른 이유: 곡의 16분음표 펄스와 같은 빠르기로 움직여 곡에 잘 붙을 것으로 보고, 리드(c)보다 57초마다 반복될 때 덜 질릴 것으로 판단했어요. 귀로 확인한 것은 아니에요.

## Urgent 분석 (수치로 추정, 귀로 확인 못 함)

- **으뜸음 F, 단조 쪽.** 조성 프로파일 상관: F 단조 0.70, F 장조 0.67 (저음 F 비중이 커서 차이는 작음). F2(87.3Hz)가 곡 전체에서 가장 강하고 모든 마디의 저음 1위예요.
- **3음이 사실상 없음.** A는 F2의 5배음(436.65Hz, -28dB)이 실제 A4(440Hz, -32dB)보다 커서 배음으로 봤고, Ab은 -31~-34dB로 약해요. 단조를 고른 이유는 곡에서 F 다음으로 강한 음이 Db4(277Hz, -23dB)이기 때문이에요.
- **"리듬만 있는" 이유.** 저음의 반음 피크들(78, 96, 105, 114Hz…)이 약 9Hz 간격이에요. 음이 바뀌는 것이 아니라 F2를 16분음표(초당 9번)로 끊어서 생긴 부수 성분으로 보여요. 화음 진행이라 부를 만한 것은 없고, 위에 얹히는 음이 구간마다 조금씩 바뀌는 정도예요.
- **빠르기.** 135 BPM. 한 박 = 정확히 19600샘플, 128박 = 2,508,800샘플. 펄스 위치는 곡 어디서나 일정해요(4구간 측정 모두 격자에서 3ms 안).

| 마디 (4마디씩) | 곡에서 강한 음 (F 배음 빼고 참고) | 얹은 화음 |
|---|---|---|
| 1-4 | F, G, Db | Fm |
| 5-8 | F, G, Db | Db |
| 9-12 | E, Eb, D | C |
| 13-16 | G, Bb, F, Db | Gm7b5 |
| 17-20 | G, D, Eb, Db | Eb7 |
| 21-24 | G, F, Db | Db |
| 25-28 | C, G, F, Db | C |
| 29-32 | F, G, Db | Fm |

곡의 F 저음은 계속 울리므로, Db·C 화음 위에서는 일부러 부딪치는 긴장감이 나요. 평화롭게 들리지 않게 한 선택이에요.

**멜로디 모티프 (8마디마다 반복, C4~Ab4):** 라b-솔-파-도 ... 레b-도 / 두 번째는 라b-솔-파-미b ... 레b-도. 끝의 레b→도 반음 하강이 기억에 남을 부분이에요.

## 층이 쌓이는 순서

| 시간 | 층 | 크기 (소리 나는 구간, 게임 기준) |
|---|---|---|
| 출격 직후 | 곡 + 베이스 선율 (곡에 섞음) | 곡 -33dB, 베이스 -33dB |
| 30초 | 낮은 "둥" 리듬 (10초에 걸쳐) | -27dB |
| 1분 | 화음·아르페지오 (10초에 걸쳐) | -33dB |
| 2분 | 빠른 리듬 + 멜로디 (10초에 걸쳐) | -33~-34dB |
| 기지 | 450Hz 위를 깎은 곡만, 베이스·층 없음 | 음량 -24dB |

효과음과 겹침: 멜로디 층 에너지의 약 70~80%가 250~520Hz에 있어요. 레벨업 마림바는 94%가 520Hz~1kHz, 광물 줍기는 520Hz~2.5kHz예요. 크기도 레벨업(-20dB)보다 13dB쯤, 가장 작은 광물 줍기(-29dB)보다 4dB쯤 작아요.

## 이음매와 박 확인

| 항목 | 이전 | 지금 |
|---|---|---|
| 반복할 때 곡 | **머리 0.9초가 무음(-77dB)이라 57초마다 약 1초 곡이 끊김** | 같은 박 위치(27마디 뒤) 소리로 채움 |
| 곡 길이 | 2,509,056샘플 | 2,508,800샘플 = 정확히 128박 |
| 처음과 끝 샘플 차이 (압축한 파일) | 0.017 | 0.001 (평소 곡 안의 변화 0.02보다 작음) |
| 리듬 층 박자 | 2차에서 빠르기는 맞췄으나 격자가 곡의 펄스와 달랐음 | 곡의 펄스 위치에 맞춤 |
| 웹에서 층 길이 | - | 48kHz에서 57초 층 2,730,666프레임, 8마디 층 682,666프레임 (어긋남 반복마다 0.04ms) |

음을 놓을 때 곡 끝을 넘는 소리는 처음으로 이어지게 쌓아서, 층에는 이음매 자체가 없어요. 귀로 들어 끊김이 없는지만 확인해 주세요.

## 함께 바뀐 것: 웹에서 필터가 동작하지 않았음

브라우저에서 직접 재 보니 웹은 음악을 Sample 방식으로 재생해서 저역 필터가 아예 만들어지지 않았어요(BiquadFilter 0개). 즉 **배포된 웹에서는 기지의 "먹먹함"과 시간이 지나며 필터가 열리는 효과가 없었어요.** 그래서 필터를 없애고 미리 먹먹하게 만든 층을 음량으로 교차해요. 웹과 데스크톱이 같은 소리를 내고, 출격은 처음부터 끝까지 또렷해요.
웹은 곡을 48kHz 스테레오로 메모리에 풀어요. 층을 그냥 늘리면 125MB에서 250MB가 되어서, 베이스는 곡에 섞고 8마디마다 같은 층은 8마디만 저장해 125MB를 유지했어요. 시작 때 가장 긴 멈춤은 1115ms → 901ms (PC, 소프트웨어 그리기 기준).

후보 파일은 `tools/make_music.py`가 게임과 같은 계산(음량·층 길이)으로 만든 것이에요. 효과음은 들어 있지 않아요.
